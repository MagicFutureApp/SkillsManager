## Fixed: scripts/release.ts 一直报 TS 错误

`scripts/release.ts` 一直被 TypeScript / IDE 标红（`TS2591: Cannot find name 'node:fs'/'node:path'/'process'`，`TS2304: Cannot find name '__dirname'`）。

根因：`scripts/` 目录既没有 `tsconfig.json` 也没有 `package.json`，没有被任何项目配置覆盖，TS 语言服务器用默认选项编译该孤立文件，不会加载 `@types/node`，也不会解析 `node:` 模块/全局变量。

修复（纯配置，不改脚本逻辑）：
- 新增 `scripts/package.json`：`@skills-manager/scripts`，`"type": "commonjs"`，devDeps 显式声明 `tsx ^4.22.3`、`typescript 6.0.3`、`@types/node ^25.9.1`。
- 新增 `scripts/tsconfig.json`：`module/moduleResolution: NodeNext`、`types: ["node"]`、`strict`、`esModuleInterop`、`noEmit`，`include: ["*.ts"]`。
- 根 `package.json` devDependencies 增加 `tsx`（根 `release` 脚本 `tsx scripts/release.ts` 之前只靠间接依赖 hoist，较脆弱）。

验证：`tsc -p scripts/tsconfig.json --noEmit` 通过（exit 0）；用 `RELEASE_ROOT` 指向临时目录跑 `tsx scripts/release.ts minor`，版本号正确递增且未改动仓库真实文件。

注意：新增依赖后建议跑一次 `pnpm install` 锁定；当前因依赖已在 hoisted node_modules 中，无需安装即可通过检查。未提交（AGENTS.md 规定未经要求不 commit）。

## 坑：pnpm-workspace.yaml 的 `scripts/*` glob 不匹配 `scripts/package.json`

`scripts/*` 只匹配 `scripts/<子目录>/package.json`（子包），**不匹配** `scripts/package.json` 本身。所以 `scripts` 一直不是合法 workspace 成员，本地 `pnpm install` 会把 lockfile 里手动补的 `scripts` importer 整段删掉，造成反复横跳。

修正：把 `pnpm-workspace.yaml` 的 `"scripts/*"` 改成 `"scripts"`，让 `scripts/package.json` 成为正式成员。改完后本地再 `pnpm install` 应不再改动 lockfile（稳定）。

提交：commit `9492f39`（首次修复：scripts/package.json + tsconfig.json + 根 tsx + lockfile 含 scripts importer）、`64e405c`（workspace glob 修正）。均未 push。

## Fixed: release workflow Homebrew 步骤崩溃（exit 2）

`.github/workflows/build-desktop-installers.yml` 的 "Update Homebrew Cask" 步骤原本 `grep release-assets/SHA256SUMS.txt`，但第二次 `actions/checkout@v7` 到 main 时默认 `clean: true` 会 `git clean` 掉未跟踪的 `release-assets/`，导致文件不存在、grep 失败 exit 2。

修复：改为 `gh release download "$TAG_NAME" -p SHA256SUMS.txt --dir "$(mktemp -d)"` 直接从已发布的 Release 拉取，不再依赖本地残留目录；并加 `-z` 空值保护。

注意：GitHub Actions 的 "Re-run" 钉死在原来触发的 commit，旧失败 run 重跑仍用旧 yml，不会用新修复。要让新 yml 生效需重新打 tag 触发（force-move tag 有破坏性，不推荐已发布 tag）。失败 run 之前其实已创建好 Release 并上传 SHA256SUMS.txt，所以「方法 B」可手动收尾 Cask（download SHA256SUMS.txt 取 mac-arm64 sha256 填进 Cask）。

## Fixed: landing Homebrew 组件的 tap 命令缺失仓库 URL

`apps/landing/src/components/homebrew-install.tsx` 最初写的 `brew tap MagicFutureApp/SkillsManager` **漏了仓库 URL**，用户照抄执行后 Homebrew 按约定去找不存在的 `homebrew-SkillsManager` 仓库，报 `remote: Repository not found` / exit 128。

## Fixed: Cask `depends_on macos` 弃用语法 warning

`brew` 报 `Calling string comparison format for depends_on macos: is deprecated`，指向 `Casks/skills-manager.rb:16`。

根因：原写法 `depends_on macos: ">= :monterey"` 是已弃用的字符串比较格式，Homebrew 新版本要求符号格式。`depends_on macos: :monterey` 语义不变（仍要求 macOS >= Monterey）。

提交：`456281b`(fix Cask depends_on 语法)，已 push（f91e71b..456281b）。

注意：本地 tap 缓存不会自动更新，需 `brew update && brew tap --repair` 才能拿到新 cask、消除 warning。Cask 第 3 行 `sha256 "5ddc..."` 仍是占位值，非真实安装哈希，需等对应版本 release yml 跑成功自动覆盖或手动补，否则 `brew install` 会 sha256 mismatch。

## Fixed/Added: 第三方 tap 必须 `brew trust` 否则 install 被拒

`brew install --cask skills-manager` 报 `Refusing to load cask ... from untrusted tap`。这是 Homebrew 4.x 对**非官方 tap**（homebrew/cask、homebrew/core 除外）的安全机制：install 前必须先 `brew trust <tap>`。

- 解决：`brew trust magicfutureapp/skills-manager`（小写 owner，与报错提示一致）后再 `brew install`。
- 已在文档补充：README `brew tap` 与 `brew install` 之间加 `brew trust magicfutureapp/skills-manager`；landing `HomebrewInstall` 组件命令同步加。
- 提交：`ef425d1`(docs: 安装说明补充 brew trust)，已 push（456281b..ef425d1）。
- 注意：trust 步骤对所有用户都是必经的，文档必须带，否则人人撞此错。raw URL 安装方式同样会触发 trust 要求。
