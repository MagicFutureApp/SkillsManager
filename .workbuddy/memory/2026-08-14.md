# 2026-08-14

## 构建脚本抽离 + TS2591 修复（已提交）

- 把 `package.json` 内联的 esbuild/tsc 构建链抽成独立 `.ts` 脚本：`apps/desktop/scripts/build-main.ts`、`apps/desktop/scripts/build-preload.ts`、`packages/utils/scripts/build.ts`（沿用 `node scripts/xxx.ts` + entry-point 守卫模式；esbuild 用 JS API 避开 pnpm shim，tsc 用 `process.execPath` 向上找根 node_modules 的 typescript）。
- `build.ts` 在 `scripts/`，若不在任何 tsconfig `include` 里，IDE 会用推断项目校验它 → pnpm 布局下 `@types/node` 不在 `typeRoots` 自动扫描范围 → `TS2591: Cannot find name node:child_process/.../process`。修复：`packages/utils/tsconfig.json` 的 `include` 增加 `"scripts"` 并 `types:["node"]`，同时**移除 `rootDir:"src"`**（否则 scripts 文件超出 rootDir 触发 TS6059）。`tsconfig.esm.json` 自带 `include:["src"]` 覆盖继承的 include，声明产物结构不变。
- 验证：`tsc -p tsconfig.json --noEmit` 与 `tsc -p tsconfig.esm.json --noEmit` 均 exit 0。
- 已分两个 commit 提交（分支 `cache-manager-v2`）：`5b972f6` refactor（含 pnpm-lock 加 @types/node）、`4268b0a` docs(AGENTS.md 耻荣对照)。`overview.md` 为会话产物，未提交。
- 教训：Node 构建脚本必须被带 `types:["node"]` 的 tsconfig 显式 include，否则 IDE 红线；单纯在 `tsconfig.json` 写 `types:["node"]` 不够，文件还得在 `include` 内。
