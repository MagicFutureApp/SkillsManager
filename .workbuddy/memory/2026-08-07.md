# 2026-08-07

## 模块格式盘点（用户问"能否把几个 app 都改 ESM"）

结论：绝大多数 app 早就是 ESM，无需改。逐 app 实情：
- `apps/landing` / `apps/cache-manager` / `apps/token-broker`：均 `type: "module"` → 已是 ESM。
- `apps/desktop` renderer：Vite 打包 → 已是 ESM。
- `apps/desktop` main + preload：`package.json` 无 `type` 字段 → CJS（根因：`build:main` 是纯 `tsc -p tsconfig.main.json` 直出、无打包器，Node/Electron 直载）。**这是唯一还跑 CJS 的部分**。

desktop main 转 ESM 的可行性：可行（Electron 41 支持 ESM main，28 起）。利好：grep 证明 `src/main` 内**无 `require(`**，代码已是 `import` 写法，无需 require→import 重写。具体改动：
1. `apps/desktop/package.json` 加 `"type":"module"`。
2. `__dirname` → `import.meta.dirname`（index.ts:44/57/125 + 2 处 test；Node 22/24 支持）。
3. `src/main`+`src/core`+`src/db` 所有相对 import 补 `.js` 后缀（约 100+ 处；Vite 解析 `.js` 无碍，renderer 不受影响）。
4. 原生 `better-sqlite3`（src/db/client.ts `import Database from "better-sqlite3"`）ESM 下靠 CJS 默认导出 interop，需实跑验证。
5. preload.ts ESM 有已知 sandbox 摩擦，单独验证。
6. `scripts/*.ts` 经 `node` 直跑，包变 ESM 后也受影响，要审计。

收益：packages/utils 可砍掉 CJS 一半（dist/cjs + commonjs 垫片 + TS1479 配对）。权衡：dual-build 已验证可用，纯为简化一个内部包做主进程迁移需掂量风险。建议分支上做 scoped spike + 跑现有 vitest 证明不回归。**尚未开始实施，仅完成可行性分析。**

## 实施：去掉 `.js` 后缀 + 引入 esbuild 打包（用户 Request B）
- 把 `apps/desktop/src/{main,core,db}` + `packages/utils/src` 共 61 文件、180 处相对 import 的 `.js` 后缀全部去掉。改用 esbuild 打包，main/core/db 不再需要 NodeNext 的 `.js` 约束。
- `apps/desktop/tsconfig.main.json` 已是 Bundler/ESNext（上一轮改）。
- desktop `build:main` = `generate-app-config` → `tsc -p tsconfig.main.json --noEmit`（类型检查）→ `esbuild src/main/index.ts --bundle --format=esm --platform=node --packages=external --outfile=dist/main/main/index.js`；新增 `build:preload`（esbuild 打包 `preload.mts`，`--external:electron`）；`build` 串联 main/preload/renderer。两个 clean 步用 `node -e fs.rmSync(...)||true`（非致命）。
- utils `build` = `(rmSync dist||true)` → esbuild 打包 `index.ts`+`cn.ts`（`--platform=neutral`，Workers 安全）→ `tsc -p tsconfig.esm.json --emitDeclarationOnly`。`cn` 子路径正确 external `clsx`/`tailwind-merge`。
- 验证：main tsc --noEmit 退出 0；renderer tsc 退出 0；esbuild 桌面 `index.js`(184KB, 0 相对 import) + `preload.mjs` 仅 import electron；utils `index.js`(0 相对 import)+`cn.js`(clsx/tw external)+`.d.ts` 生成。

## 沙箱环境关键坑：safe-delete / genie-trash 拦截删除
- 本沙箱用 genie-safe-delete 包装了 `rm`/`mv`/`fs.rmSync`/`PowerShell Remove-Item`，且 trash 子进程 ETIMEDOUT → **任何删除都失败**（含 `prettier --write` 的写回 rename、`esbuild` 覆盖写已有文件）。
- 因此：① 无法删除文件（遗留 `apps/desktop/src/main/ipc/locale.test.ts.new` 与 `utils/dist` 旧文件删不掉）；② 无法在沙箱重跑「先清 dist 再打」；③ 17 个文件需 `prettier --write` 但写不进沙箱。
- 能用的通道：单文件 `sed -i`（成功）、`Edit`/`Write` 特权工具（覆盖写可行）、esbuild 写**不存在**的新文件（可行）。写已有文件一律 Access denied。
- 应对：删除类操作交回用户真实环境做（`pnpm install` / `pnpm run format` / 手动 `rm` 遗留文件）。本会话产物（dist 入口文件）已用「temp 目录 esbuild → Write 工具覆盖写」验证为有效。
