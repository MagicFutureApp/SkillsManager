## best-100 数据主源：latest -> UTC 日期路径（防静默陈旧）

### 机制结论（用户提问驱动）
- 上游 `data/` 同时有 `latest/` 和按日期目录（`2026-08-16`…`2026-09-21`）。`raw.githubusercontent` 无服务端 latest 魔法，`latest/` 只是仓库里一份"最新快照副本"。
- 用 `latest` 时两种失败：A) 我们抓不到 GitHub(404/网络) → 失败分支保留 `existingCsv`，状态 `failed`（可见）；B) **上游当天没刷新 `latest` 但文件仍 200** → 成功分支覆盖 KV 并写 `success`，UI 显示"今天同步成功"却实际是上一天数据——**静默陈旧**（最危险）。CSV 无日期列，无法从内容识别陈旧。

### 改动（用户选"仅 UTC 日期路径"，并要求失败/404 不更新 KV 数据）
- `cache-manager/src/lib/source.ts`：`BEST_100_SOURCE_URL` 常量 -> `BEST_100_BASE_URL` + `getBest100SourceUrl(now=new Date())` 按 UTC 日期拼 `data/${YYYY-MM-DD}/rankings/best-100.csv`；并导出 `dateKey`。
- `cache-manager/src/lib/scheduler.ts`：`source = getBest100SourceUrl(now)`；删除本地 `dateKey`，复用 source.ts 导出；`dateKey` 用 `toISOString().slice(0,10)` = UTC，与上游目录对齐。
- **失败/404 行为已满足"不更新 KV 数据"**：`runScheduledFetch` 失败分支 `writeStore({ csv: existingCsv, meta })` 保留旧 CSV，只更新 meta（attempts/lastError/status=failed）——meta 写入是为跨 cron 槽重试计数与 UI 可见性必需；CSV 内容永不被动。
- 验证：`tsc -p apps/cache-manager/tsconfig.json --noEmit` -> WORKER_TSC_EXIT=0。grep `BEST_100_SOURCE_URL|/latest/` 于 cache-manager/src 无匹配。

### 关联坑（已提示用户，未改）
- cron 窗口 UTC 00:30-01:30；若上游每天发布晚于此时（如 UTC 03:00），纯日期路径会连续 404、当天一直 `failed` 并展示昨天数据。用户已知情选择。
