## 已修复：cache-manager Worker typecheck 报错（TS2688）
- 根因：`apps/cache-manager/package.json` 把 `@cloudflare/workers-types` 钉到**不存在**的版本 `^4.2025.9.0`（Cloudflare 用日期版本如 `4.20250909.0`，该精确版本从未发布）→ `pnpm install` 报 ETARGET → 类型库未装 → `tsc` 抛 TS2688。这是真 bug，不是沙箱限制。
- 修复：版本改为真实存在的 `^5.20260920.1`（匹配 Worker `compatibility_date: 2026-01-01`）；沙箱内用 node 自带 npm 装到 `apps/cache-manager/node_modules/`，`tsc --noEmit` 现已 0（WORKER_TSC_EXIT=0）。
- 注意：沙箱无 pnpm，靠 npm 直装；用户侧 `pnpm install` 会按新版本正确解析。建议安装前删 `apps/cache-manager/node_modules` 避免与 pnpm 结构冲突。

## 已修：cache-manager `wrangler dev` 启动报 `spawn EFTYPE`

- 现象：本地起 cache-manager（wrangler dev）失败，log 核心 `Error: spawn EFTYPE`（errno -4028, syscall spawn），Miniflare 起本地 workerd 子进程时报。
- 根因（非代码）：`apps/cache-manager/node_modules/@cloudflare/workerd-windows-64/bin/workerd.exe` **二进制损坏/被 Windows 拦截**（49MB，spawn 即 EFTYPE）；而根目录 hoisted 那份 `node_modules/@cloudflare/workerd-windows-64/bin/workerd.exe` 正常（90MB，`workerd 2026-07-21`）。wrangler 从 apps/cache-manager 跑，解析到坏的那份。
- 验证手法（决定性）：用 `child_process.execFileSync(exe,['--version'])` 分别跑两份 —— 坏份 FAIL EFTYPE、好份 OK，排除"shim/spawn 路径"问题，定位为二进制本身损坏。
- 修复：把根目录正常 exe 复制到坏的那份（`fs.copyFileSync` 覆盖真实文件，非 junction），复测 OK。
- 说明：`apps/cache-manager/node_modules/@cloudflare/workerd-windows-64` 是真实目录（isSymlink=false），复制直接落到真文件；全仓仅 2 份 workerd.exe（root + cache-manager），`workerd` 包装包 require.resolve 即指向 cache-manager 这份，已修。
- 若复发：多半是某次 `pnpm install` 拉到损坏二进制；删 `apps/cache-manager/node_modules` 重装即可。node_modules 被 gitignore，改它无风险。
