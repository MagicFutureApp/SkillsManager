## cache-manager 加 CORS 支持（可配置来源域名）
- 桌面端 dev（`http://localhost:3700`）直连 cache-manager Worker 触发 CORS 报错（无 `Access-Control-Allow-Origin`）；根因是该 Hono Worker 完全没有 CORS 处理
- 改为可配置环境变量 `CORS_ALLOWED_ORIGINS`（wrangler.jsonc `vars`，默认 `*`）：
  - `*` 表示允许所有来源
  - 逗号分隔的具体域名列表：仅当请求的 `Origin` 命中时才回显该 `Origin`（精确匹配，更安全），未命中则不返回 CORS 头 → 浏览器拦截
  - 命中具体域名时额外加 `Vary: Origin`
- 关键实现点（踩坑）：
  1. Hono `app.use("*", withCors)` 必须在 `await next()` **之后**往 `context.res.headers` 上 `.set`，否则 pages 路由返回的 `new Response(...)` 会丢掉中间件设的头
  2. OPTIONS 预检没有对应 route，Hono 在 `next()` 阶段会抛错 → 改为在 `withCors` 顶部对 OPTIONS 直接 `context.res = new Response(null, {status:204})` 短路，不调 next()
  3. `context.env` 在 preflight 路径下可能是 `undefined`，读取 `CORS_ALLOWED_ORIGINS` 必须写成 `context.env?.CORS_ALLOWED_ORIGINS` 避免抛错 500
- 修改文件：`apps/cache-manager/src/app.ts`（withCors 中间件 + parse/resolve 助手）、`worker-env.ts`（WorkerBindings 加 `CORS_ALLOWED_ORIGINS?`）、`wrangler.jsonc`（vars 段）、`app.test.ts`（新增 CORS 用例：200/202/404/503/OPTIONS + 域名允许回显 + 未列出拒绝）
- 验证：cache-manager `tsc --noEmit` 0 错；vitest 25 passed（含 CORS 用例）
- 部署：需由用户在 `apps/cache-manager` 跑 `pnpm deploy`（线上 Worker，我未执行）

## 发现页数据流 × cache-manager 契约一致性评审（纯分析，未改代码）
- 评审报告：`.workbuddy/artifacts/2026-08-04-discover-dataflow-review.md`
- 结论：核心契约方向对（不硬编码 generation / total 取 `pagination.total` / 客户端页内搜索），但有 2 个 P0 + 5 个 P1
- **纠正本文件上方"对齐 cache-manager 契约"一节的两条自评**（当时以为已处理，实际失效）：
  1. **「处理 202 warming（Retry-After 重试）」实际未生效** —— `Retry-After` 不是 CORS-safelisted 响应头，`app.ts:136-139` 的 withCors **没有设 `Access-Control-Expose-Headers`**，renderer 里 `res.headers.get("retry-after")` 恒为 null，永远走兜底 2s。修法二选一：请求移到 main process（Node 无 CORS 限制），或 Worker 补 `Access-Control-Expose-Headers: Retry-After, X-Cache, X-Catalog-Generation`。**两边要成对改**
  2. **「503 回退 previous.generation」实现不完整** —— 回退后不更新 `pageCount`/`total`、也不切 `currentGenerationRef`，导致跨页混用两代（spec `:79` 明文禁止）且每翻页重复失败一次。应"整次会话锁定一代"
- **架构层面最大问题（P0）**：HTTP 写在 renderer 裸 `fetch`（`discover-data.ts:52,70`），完全绕过 preload/IPC/core/db（`preload.ts` grep catalog 零命中）。而 spec `2026-07-29-...-design.md:33` Topology 写的是 `Electron main process -> Worker`，`:28` 更把「Electron renderer 或 main process 接入」列在**第一版不包含**里。隐患：base URL 构建期写死不可配置；且一旦 Worker CORS 收紧 allowlist，打包后 `file://` 的 Origin 是 `null`，无法匹配任何 allowlist → 线上直接全挂
- 其他确认的坑：404（generation 轮换）未识别且 `currentGenerationRef` 永不刷新 → 挂机超 ~12h 必现无法恢复的加载失败；`refetch` 是死代码（hook 导出但 `discover-page.tsx` 没传下去），error 是终态无重试按钮；搜索按钮无 onClick 且搜索时分页器被隐藏；外链用裸 `target="_blank"` 未走已有的 `openExternalUrl` IPC（且白名单只允许 github.com / sk.magicfuture.app，需放行 skills.sh）
- `features/discover/` 整个目录仍 untracked 且零测试；`docs/superpowers/plans/` 下无 catalog cache 实施计划文档；`AGENTS.md:13`（称 cache-manager 为"占位"）和 `:174`（区域列表缺 Discover）已过时
